  Cache Hit Counter Reset Bug in `MitmproxyAddon.response`
  - **Context**: In `MitmproxyAddon.request()`, when a cache hit occurs (`cached_resp` is not `None`), it creates a

    `response(flow)` hook callback for that flow. In `MitmproxyAddon.response(self, flow)`, there is no check to
    determine if `flow.response` was generated by the cache interceptor itself. Consequently, `response()` parses
    `req_data` and `resp_data` and invokes `self.interceptor.intercept_response(url, req_data, resp_data)`, which calls

    `flow.is_cached = True`) and check this flag in `MitmproxyAddon.response()` before calling `intercept_response()`.

  Unnormalized System Prompt Comparison Bug in Semantic Cache Lookup
  - **Context**: In `HybridCacheStore.get()`, lines 201-203 attempt to enforce exact system prompt equality before
    calculating user turn semantic similarity:
    ```python
    if payload.get("system") != stored_payload.get("system"):
        continue
    ```
    However, `payload` is the raw, unnormalized request dictionary passed into `get()`, whereas `stored_payload` was
    parsed from `stored_norm` (where timestamps, UUIDs, and task IDs were replaced with placeholders like `<TIMESTAMP>`
    and `<UUID>`). If the incoming request's system prompt contains any transient timestamp or task ID,
    `payload.get("system")` (unnormalized) will not equal `stored_payload.get("system")` (normalized). This causes
    `HybridCacheStore.get()` to reject valid semantic matches whenever system prompts contain normalized elements.
  - **Recommendation**: Compare `target_payload.get("system")` (which was extracted from `target_norm` after
    `normalize_payload()`) against `stored_payload.get("system")`.
  - **Proposed Code Change**:
    ```diff
    --- a/apps/sandbox-executor/src/sandbox_executor/token_reduction/hybrid_cache.py
    ```

  Non-Atomic `hit_count` Counter Increments Subject to Concurrency Races
  - **Context**: In `HybridCacheStore.get()`, when updating `hit_count` during exact prefix hits (L160-L163) and
    semantic similarity hits (L215-L218), the code reads `hit_count` into a Python integer variable from `SELECT` and
    executes: `cursor.execute("UPDATE prompt_cache SET hit_count = ? WHERE key = ?", (hit_count + 1, prefix_key))` Under
    concurrent MITM proxy request handling, reading `hit_count` in Python and writing `hit_count + 1` back creates a
    read-modify-write race condition, leading to lost updates.
  - **Recommendation**: Use atomic SQL arithmetic expressions for updating counter values (`hit_count = hit_count + 1`).
  - **Proposed Code Change**:
    ```diff
    --- a/apps/sandbox-executor/src/sandbox_executor/token_reduction/hybrid_cache.py
    ```
